# WorkAccounting — локальна система обліку робіт

React + TypeScript + Vite frontend, ASP.NET Core 10 backend, SQLite file database.

## Windows запуск

1. Встановіть .NET 10 SDK і Node.js 22+.
2. Розпакуйте ZIP у папку без кирилиці в шляху (наприклад, `C:\WorkAccounting`).
3. Запустіть `setup.bat` (перший раз потрібен інтернет для NuGet/npm).
4. Створіть `backend\admin-password.txt` і запишіть в нього **один рядок** з власним унікальним паролем (мінімум 10 символів, без пробілів наприкінці). Не комітьте цей файл.
5. Запустіть `start.bat`.
6. Відкрийте `http://127.0.0.1:5173` (або `http://localhost:5173`). Логін `admin`, пароль із файлу.

База `backend/workaccounting_v2.db` створюється автоматично при запуску backend. Перший admin створюється, лише якщо ще немає жодного адміністратора. Після першого запуску можна прибрати пароль із файлу, але тоді запуск через `start.bat` потребує змін — альтернативно задавайте змінну `WORK_ADMIN_PASSWORD` вручну.

### Запуск вручну

PowerShell 1:
```powershell
cd backend
$env:WORK_ADMIN_PASSWORD = 'SET_YOUR_OWN_LONG_PASSWORD'
dotnet run --urls http://127.0.0.1:5088
```
PowerShell 2:
```powershell
cd frontend
npm install
npm run dev
```

## Порядок роботи

1. Адміністратор створює контракт.
2. Додає автомобілі й дільниці до контракту.
3. Створює роботи з нормативом годин, вибираючи авто та дільницю.
4. Додає матеріали в міні-склад і оформлює прихід.
5. Закріплює кількості матеріалів за конкретними роботами.
6. Створює логіни користувачів з ролями Admin, Manager або Master.
7. Майстер вносить щоденний прогрес роботи й людино-години.
8. При досягненні 100% backend в одній SQLite-транзакції записує виконання і списує закріплені ТМЦ. За дефіциту матеріалів завершення не проводиться.
9. Керівник переглядає панель та звіти, експортує CSV (відкривається в Excel).

## Ролі

- Admin: керує довідниками, матеріалами, користувачами, прогресом; переглядає звіти.
- Master: вносить щоденний прогрес, переглядає довідники та звіти.
- Manager: переглядає довідники й звіти.

## Відомі обмеження — важливо

Це **функціональний MVP**, а не готова для виробничої експлуатації ERP. У поточній версії:
- Немає імпорту вихідного Excel DESNA; дані вводяться вручну.
- Звіти експортуються в CSV, не в .xlsx.
- Немає аудиту редагувань, повернень ТМЦ і коригувань завершених робіт.
- Ролі майстра ще не обмежені окремими контрактами або дільницями.
- Для завершення роботи треба мати достатній залишок усіх закріплених ТМЦ.
- Немає автоматизованих інтеграційних тестів і підтвердженого запуску на вашому Windows.
- Локальна HTTP-сесія зберігається в sessionStorage, тому система призначена лише для довіреного локального комп'ютера, не для відкритого інтернету.
- Зв'язок роботи з дільницею та авто повинен належати тому самому контракту; це потребує додаткової серверної перевірки перед production.
- Історичні щоденні записи не видаляються; повноцінне коригування та сторнування — наступний етап.
- Змінювати прив'язані ТМЦ після завершення роботи не слід — потрібне додаткове серверне блокування.

Не використовуйте реальні критичні дані до перевірки сценаріїв на тестовій базі. Регулярно копіюйте файл SQLite при зупиненому backend.

## Ярлик Windows — запуск як програми

1. Встановіть .NET 10 SDK та Node.js 22+, один раз запустіть `setup.bat`.
2. **Перший запуск:** створіть `backend/admin-password.txt` зі складним паролем (≥10 символів). Після першого створення адміністратора пароль із файлу можна прибрати.
3. Двічі натисніть **`install-shortcut.bat`** — з'явиться ярлик **WorkAccounting** на робочому столі.
4. Подвійний клік на ярлику запускає локальний API/UI (якщо не працюють) і відкриває вікно Microsoft Edge у режимі застосунку; без Edge використовується браузер за замовчуванням.
5. Для роботи потрібен запущений ПК; локальні процеси працюють у вікнах командного рядка. Це ярлик до локального вебзастосунку, **не інсталяція нативного EXE**.
6. Перевірка на Windows CI: `tests/windows_smoke.ps1`. Основна база в `backend/workaccounting_v2.db`; перед оновленням створіть резервну копію SQLite з урахуванням WAL.

**Безпека:** за замовчуванням слухає лише `127.0.0.1` і не відкриває сайт у мережі. Для доступу зі смартфонів потрібен окремий захищений HTTPS-доступ, а не відкриття Vite-dev сервера.
